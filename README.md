## Overview
For this project we were tasked with implementing different search algorithms to solve the eight-puzzle, a puzzle consisting of a 3x3 grid with 8 numbered tiles and on blank space. The solution to the puzzle is a predetermined configuration of the 8 numbered tiles, and is reached by choosing a tile adjacent to the empty slot and sliding it into the empty slot, leaving an empty slot where the tile was. The process is then repeated using whichever slot is empty until the goal configuration is reached. The algorithms we implemented were meant to try and find the optimal solution to each 8-puzzle, meaning it solves the puzzle in as few steps as possible.

To obtain the optimal solution, we use the following algorithms:
- **Uniform Cost Search (UCS)**  \
Uniform Search Cost keeps track of each potential set of moves as it goes, with each move having equal cost. It expands whichever state has the smallest total cost so far. As a result, it will eventually find the optimal solution of lowest cost, but typically will explore unnecessary states along the way as it has no guidance towards the goal state. 

- **A\* with Misplaced Tile heuristic**  \
This A* Search algorithm works similarly to UCS, keeping track of the path with the lowest total cost. However, we also use a heuristic as a guide to help the algorithm estimate the best direction for the algorithm to be searching. In this instance, the heuristic is how many tiles are misplaced compared to their position in the solution.

- **A\* with Euclidean Distance heuristic**  \
This A* Search works similarly to the one above, except the heuristic measures the straight-line distance from each tile’s current position to its goal position and sums them up. It is a more costly heuristic to compute, but is generally stronger.

## Implementation
Our implementation followed an object-oriented design centered around the ‘Problem’ class, which holds the initial puzzle state, the goal state, and the functions required to run our three algorithms. A puzzle state is stored as a flat vector<int> with an index for the blank slot. Legal moves are generated by swapping the blank slot with an adjacent tile as long as the move is in-bounds. The three search functions for the algorithms are run_UniformCost(), run_AStarMisplaced(), and run_AStarEuclidean(). All three search algorithms use a priority queue ordered by f(n) as the frontier. We implemented a graph search rather than a tree search, which lets us avoid having to re-expand already improved states. Our main.cpp runs the program, providing a UI that allows the user to perform a search on the default puzzle, or to enter their own. They can then choose an algorithm to run on their chosen puzzle, get and view their result, along with a full final solution. They can then either run another algorithm on it or exit the solver.

## Difficulties and Challenges
For difficult test cases, specifically the test case #5, the solver can generate more than 90,000 nodes. Therefore, it will be a disaster to use linear search algorithms because we would have O(number of states), which is O(90,000) in this case, at every expansion. In order to reduce the runtime complexity—in other words, to optimize the code and make searching for and comparing states faster, we use a hash table called ‘best_g’. This hash table contains a unique key for each state and a value to store the smallest g. With hashing, the cost for searching and comparing will be minimized. It is always O(1) instead of O(n) and nicer to be put in a loop.

Several challenges arose in the process of properly implementing the three search algorithms. For instance, for the Euclidean Heuristic Search, the variables for the heuristic and totalCost we first them initialized as integers, so when the euclideanDistance function calculated its value as a double, it would be rounded to an integer and result in an incorrect heuristic. Another issue we ran into was earlier versions of our implementation would repeatedly search for blanks and had a possibility of being off by one when on the borders. We resolved this problem by including the index of the blank spot as a Node member variable and updating it every time, along with using four operator functions (up, down, left, right). This allowed the useAlgor functions to run at O(n).

## Summary

From our results, we can see that all three algorithms behave similarly on puzzles with very small solution depths. In the Goal State and Very Easy cases, all three approaches expand almost no nodes and reach the same optimal depth immediately. As the puzzles increase in complexity, both A* algorithms continue performing efficiently, while Uniform Cost Search already begins to fall behind. The difference becomes more dramatic once we reach the Difficult puzzle. Uniform Cost Search expanded over 91,000 nodes, while A* with Misplaced Tile Expanded only about 9,120 nodes, and A* with Euclidean Distance needed just 1,067 expansions. The maximum queue size follows the same trend, with both heuristic variants using significantly less space.

The impossible puzzle also demonstrates the benefit of the heuristics, as both A* algorithms used significantly less memory to exhaust the state space compared to UCS. Overall, these tests show that heuristics make a major difference as puzzle difficulty increases. The Euclidean Distance heuristic consistently performed best in both time (fewest nodes expanded) and space (lowest maximum queue size), while still guaranteeing optimal solution depth.
